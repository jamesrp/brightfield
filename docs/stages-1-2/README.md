# Stages 1 and 2: static full-hex tiles

First batch after the approved Stage 0 pilot, following [issue #2's four-PR plan](https://github.com/jamesrp/brightfield/issues/2#issuecomment-6815889758). Branch `art/stages-1-2-static` starts from main at `d201c7789b18c863377bd0addff628c0db723837` (merged pilot #5).

## Scope

Sixteen 1024×1536 transparent PNGs replace the Stage 1 and Stage 2 atlases in the tile manifest. Stage 0, the other three futures, Paragons, legacy atlases and gameplay code are unchanged. Each plot uses the existing earth kerb, with its interior RGBA pixels copied exactly. The top face follows spec v2: centre (512,1130), half-width 480, half-height 354.7 and 37.8 px kerb.

- Stage 1: gas plant, empty motor garage, orchard, water tower, terrace houses, artisan workshop, recycling depot and city park.
- Stage 2: rotor-free turbine towers, empty charging hub, greenhouse, rain garden, living-roof flats, robot foundry with empty mounting pedestal, compost yard and old-growth woodland.
- Moving vehicles, turbine blades, robot arm, saw blade, steam and other actor/effect art are omitted. Smoke is emitted by the manifest where appropriate, rather than painted into the PNG.

Only final assets, prompts/provenance, reproduction scripts, text QA records and the two town close-ups are committed. Raw generations, rejected candidates, fitted sources and broader contact sheets remain in the external private archive.

## Generation and exact-geometry completion

Every tile was separately generated with built-in imagegen. The existing earth slab supplied plot geometry and the approved Stage 0 paintings supplied style references. Exact prompts, refinement prompts and final checksums are recorded in `../art-provenance.json`. `source-selection.json` identifies the accepted raw source for each tile.

1. `art:fit` aligns the source, clips only the allowed columns/bottom boundary, and applies the family sides.
2. `finish-tile.cjs` completes small transparent ground-edge gaps from the **already-painted earth slab**, restricted to the exact top-face polygon and pixels whose original alpha is below 200. All other tile painting pixels are preserved. This is source compositing, not procedural texture generation. The script rejects more than 6,000 incomplete ground pixels rather than covering a substantially wrong plot.
3. The final two kerb faces copy the authoritative slab's RGBA pixels exactly. The existing family-aware regression checks these shared pixels.

All accepted tiles use normal alignment. Initial unaligned greenhouse and recycling-depot candidates clipped too much perimeter; normal alignment plus the narrowly bounded ground completion preserves their roofs and planting. The woodland was regenerated to preserve headroom. The Stage 1 water tower was edited so its front grass tip reaches the exact plot boundary without a second kerb inside the face. The foundry’s early corner-gap and old-fashioned architecture candidates remain archived but are not shipped.

## Reproduce and verify

Set `BRIGHTFIELD_ART_ARCHIVE` to the private archive root. `source-archive.json` records source filenames, byte counts and SHA-256 values without putting the images in git.

```
npm ci
BRIGHTFIELD_ART_ARCHIVE=/path/to/archive node docs/stages-1-2/rebuild.cjs
npm run art:check
npm test
npm run art:preview
sha256sum -c SHA256SUMS.txt
```

The rebuild checks every accepted source hash before use. Normal tests and previews need only the committed final images. `qa/composition.json` records each fit, clipped-pixel count, ground completion count and final checksum. Text test and geometry results are under `qa/`.

## Verification results

- All 24 manifest tiles pass `art:check`, with 100% solid top faces and edge deviations within 0.5 px.
- All 87 regression tests pass, including the exact family-kerb pixel checks.
- Rebuilding all 16 new tiles from verified sources produces byte-identical PNGs; see `qa/reproduction.json`.
- The largest fit clips 2,460 pixels, and the largest bounded ground completion fills 4,337 pixels. Per-tile details are in `qa/composition.json`.
- Both final town close-ups passed independent visual review: no visible second plates, clipped architecture or lane encroachment; subjects remain readable at town size.
- Review uses the real renderer harness, not physical-device gameplay testing.

## Remaining static batches

Each subsequent batch gets its own branch from the then-current main, after checking the latest issue comments and open PRs to avoid duplicate work. Refresh main and regenerate the checksum file after any rebase; do not branch from this unmerged art branch.

1. Leaf: eight tiles using the existing garden kerb. Preserve headroom by growing trees upward rather than letting foliage cross the columns. Keep the garden tram and other moving pieces out of the bases.
2. Star: eight tiles using the existing alloy kerb. Keep the maglev pod and other actors separate; retain static light fixtures for later glow layers.
3. Magic: eight tiles using the existing arcane kerb. Preserve the purple/gold language and reserve moving orbs, wisps and glow layers for later rounds.

These batches have no art dependency on one another, but their shared manifest/provenance/checksum edits need reconciliation against current main. Each requires its own real-renderer town close-up and passing art, regression and checksum checks.
